{% comment %} Everything about a ticket that can change: the heading badges, the conversation, the reply box and the control rail. ticket_detail.html includes this file, and both POST endpoints render it back aimed at #ticket-workspace — so a reply that moves the ticket to "Awaiting vendor" updates the badge and the rail in the same swap, and a reloaded page is the same markup by construction. Both forms keep method, action and the CSRF token, so with scripting off they POST and the view redirects back here. hx-post sits alongside, never instead. Status is written as queue_status_label throughout — "Awaiting your reply" is the vendor's wording and would read backwards in here. Every place a vendor's own words land — the subject, a thread entry, the linked facility — carries break-words, the same as the vendor's side of this thread (support/partials/ticket_message.html). An API ticket is where someone pastes a callback URL, a request id or a JWT, and none of those offer the browser a place to break: without this the subject alone drags the page to 806px at 375px wide, and a pasted token is clipped away by the card's own overflow rather than wrapped.
