{% comment %} Django messages as careui alerts — the page's one flash region. The #flash-messages wrapper always renders, even with nothing to say, for two reasons: an out-of-band swap needs a live element to aim at, and a permanent aria-live region is announced far more reliably than one that appears with its content already inside it. OOB contract — a partial response that needs to raise a flash on a page it is not otherwise re-rendering appends: {% include "components/messages.html" with oob=True %} to the end of the fragment it returns — never with `only`, which would cut the include off from `messages` and quietly swap the region empty. That marks the wrapper hx-swap-oob, so htmx drops the alerts into the live #flash-messages wherever it sits on the page. The swap style is innerHTML on purpose: the wrapper itself — id, role, aria-live — stays put and only the alerts inside it change, which is what makes the announcement work. Include this partial at most once per page; a second copy would give the OOB swap two targets and Django's message store is consumed on first render. {% endcomment %} {% load i18n %}
