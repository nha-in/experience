{% comment %} Django messages as careui toasts — the page's one flash region. Pages get it through components/toaster.html, which pins it to the foot of the viewport; the only direct include is the out-of-band one below. The #flash-messages wrapper always renders, even with nothing to say, for two reasons: an out-of-band swap needs a live element to aim at, and a permanent aria-live region is announced far more reliably than one that appears with its content already inside it. OOB contract — a partial response that needs to raise a flash on a page it is not otherwise re-rendering appends: {% include "components/messages.html" with oob=True %} to the end of the fragment it returns — never with `only`, which would cut the include off from `messages` and quietly swap the region empty. That marks the wrapper hx-swap-oob, so htmx drops the toasts into the live #flash-messages wherever it sits on the page. The swap style is innerHTML on purpose: the wrapper itself — id, role, aria-live — stays put and only the toasts inside it change, which is what makes the announcement work. A success or info message fades out after a few seconds; an error or a warning stays until it is dismissed (.ui-toast--fleeting in careui.css). Include this partial at most once per page; a second copy would give the OOB swap two targets and Django's message store is consumed on first render. {% endcomment %} {% load i18n %}
