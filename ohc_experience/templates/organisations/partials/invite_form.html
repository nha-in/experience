{% comment %} The invite form. team.html includes it and TeamView swaps this same file back in — empty after a successful invite, or carrying its errors after a bad one. The ordinary swap files the new row into the invitations tbody, so everything else on the response (this form, the stacked card, the flash) travels out of band. On a validation error the response is a 200 whose only content is this form marked hx-swap-oob, which leaves the table untouched. Context: form (InvitationForm), oob — True when this rides on a response as an out-of-band swap. No hx-indicator here on purpose, unlike the row actions: leaving it off makes the form itself the indicator, which is what lets the spinner inside the button light up (.htmx-request .htmx-indicator). Naming #nav-progress instead would move the htmx-request class off the form and the spinner could never show. This is the same arrangement organisation_form.html uses. No-JS contract: method, action and the CSRF token are real, so without htmx this POSTs the team page and the view redirects back as it always did. {% endcomment %} {% load i18n careui %}
