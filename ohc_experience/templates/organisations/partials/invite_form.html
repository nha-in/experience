{% comment %} The invite form. team.html includes it and TeamView swaps this same file back in — empty after a successful invite, or carrying its errors after a bad one. The ordinary swap files the new row into the invitations tbody, so everything else on the response (this form, the stacked card, the flash) travels out of band. On a validation error the response is a 200 whose only content is this form marked hx-swap-oob, which leaves the table untouched. Context: form (InvitationForm), oob — True when this rides on a response as an out-of-band swap. hx-indicator="this", unlike the row actions: the form itself is the indicator, which is what lets the spinner inside the button light up (.htmx-request .htmx-indicator). The #nav-progress it would otherwise inherit from the shell takes the htmx-request class off the form, and the spinner could never show. profile_form.html does the same.
